critical-script는 **메인 JS 번들보다 먼저 실행되어야 하는 작업**을 _최소한의 코드_로 수행하기 위한 도구입니다.

- 메인 JS 번들이 로드되기 전에 시작해야 의미가 있는 작업만 포함하기를 권장합니다. 예를 들어 API 프리페치나 리소스 프리로드, 웹뷰 네이티브 브리지 호출 등이 있습니다.
- 동기 연산이나 대규모 라이브러리 사용처럼 무거운 로직은 일반 JS 번들에 두세요.
- 기본 `outputSizeLimit` 8192바이트가 이 원칙을 빌드 단계에서 강제합니다. 자세한 근거는 [API 레퍼런스 > outputSizeLimit](./api-reference.md#outputsizelimit)를 참조하세요.

## 언제 사용하나요

critical-script는 다음 두 조건을 모두 만족할 때 가장 효과적입니다.

1. **실행 시점이 중요한 작업일 때**: 메인 JS 번들이 로드되기 전에 실행되어야 의미가 있는 작업(API 프리페치, 리소스 프리로드, 웹뷰 네이티브 브리지 호출, 스켈레톤 UI 보정)입니다.
2. **인라인 코드가 한두 줄을 넘을 때**: 어느 정도 로직을 담고 있고 자주 수정되거나 여러 곳에서 공유된다면 TypeScript의 정적 검사·모듈 시스템·IDE 지원이 유용합니다.

다음과 같은 경우에는 critical-script를 사용하지 않아도 됩니다.

- **메인 JS 번들이 로드된 이후에 실행해도 되는 작업**은 일반 번들에 둡니다.
- **무거운 로직이 포함된 작업**은 일반 번들에 둡니다.
- **인라인 코드가 1~2줄 수준이고 거의 수정되지 않는 작업**은 `<script>` 태그에 직접 작성합니다.
